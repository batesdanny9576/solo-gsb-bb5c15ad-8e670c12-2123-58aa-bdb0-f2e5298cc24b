# 舞台走位校验系统

一款舞台走位（Blocking）校验 Web 应用：在「舞台区域连接图」上标注各区域间的通行耗时与**通道封闭时段**，为演员按时间下达「到位口令」，系统从上一口令时刻出发**逐边推演**相邻口令之间的行程——进入某条连接若会与封闭时段重叠，可在区域等待或改走其他路径——以**最早到达时刻**计算所需秒数，标出**无法按时抵达**的区段并给出**所需秒数 / 可用秒数 / 等待位置与时长**，支持编辑后即时重算与一键导出 Markdown 校验报告。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无任何前端构建步骤）。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（Web 服务监听容器内 `3000` 端口，Compose 已映射到主机 `3000` 端口）

> 首次启动时，若数据文件不存在，系统会自动写入内置示例数据（9 个舞台区域、11 条连接——其中 3 条配置了封闭时段、3 位演员、12 条口令，含刻意设计的「改道」「等待」「超时」与「不可达」演示区段）。

## 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | Web 服务监听端口（Compose 中映射为主机 3000 端口） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 数据文件 `data.json` 存放目录 |

Compose 默认将数据目录挂载为命名卷 `stage-data` 以持久化修改；执行 `docker compose down -v` 删除卷后重启即可恢复示例数据（也可在页面右上角点击「恢复示例数据」）。

## 本地开发（不用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

要求 Node.js ≥ 18。

## 功能说明

- **舞台区域**：维护区域名称与备注（如 舞台中央、侧台右、后台化妆间）。
- **区域连接**：维护无向连接、通行耗时（秒）与**通道封闭时段**（可配置多个起止秒数区间），同一对区域仅允许一条连接。
- **演员**：维护演员姓名与角色。
- **到位口令**：按「演员 + 目标区域 + 时间」下达口令，时间支持 `90`（秒）或 `01:30`（分:秒）两种输入格式。
- **校验结果**：对每位演员，将其口令按时间升序排列，从上一口令时刻出发，用时间依赖最短路（Dijkstra）逐边推演相邻口令两区域间的最早到达时刻：
  - ✅ **可达**：所需 ≤ 可用，显示余量秒数与实际路线；
  - ❌ **超时**：所需 > 可用，红色高亮并显示「所需 X 秒 / 可用 Y 秒、缺口 Z 秒」；
  - ⛔ **不可达**：两区域在连接图上不连通。
  - 若推演艺程中发生等待，结果区会标注**等待位置与时长**及预计到达时刻，路线列展示含等待标注的实际路线。
- **即时重算**：任何新增 / 编辑 / 删除操作（含封闭时段调整）保存后立即重新校验并刷新结果。
- **导出报告**：点击「导出校验报告」下载 Markdown 格式报告（含汇总表与每位演员的区段明细，路线列同步给出动态推演的出发时刻、等待标注与逐边到达时刻）。
- **级联一致性**：删除区域会同时删除相关连接与口令；删除演员会同时删除其全部口令。

## 通道封闭时段规则

- 每条区域连接可配置 **多个封闭时段**，格式为起止秒数区间 **`[start, end)`（左闭右开）**：第 `start` 秒起封闭，第 `end` 秒恢复通行（`end` 时刻即可进入）。
- 校验时从上一口令时刻出发，按通行耗时逐边推演：演员在时刻 `t` 进入一条耗时 `s` 秒的连接，会占用通行区间 `[t, t+s]`；若该区间与该连接的任一封闭时段重叠，则**不能在此刻进入**。
- 遇封闭时系统自动选取更早到达的方案：
  - **在区域等待**：原地等待至封闭结束（`end` 时刻）再进入，等待时长计入所需时间；
  - **改走其他路径**：若绕行能更早到达，则自动改道。
- 以**最早到达时刻**判定结论：所需时间（含等待）≤ 可用时间为按时，否则为超时；两区域在图上不连通为不可达。
- 保存时系统会自动过滤非法区间（非整数秒、`end ≤ start`），并将重叠或相邻的区间**排序后合并**。
- **数据兼容**：旧数据文件中没有封闭时段字段的连接会自动按「无封闭」处理，无需手工迁移。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/data` | 获取全部数据（区域 / 连接 / 演员 / 口令） |
| GET | `/api/validate` | 执行走位校验，返回区段级结果（含逐边明细与等待信息） |
| GET | `/api/report` | 下载 Markdown 校验报告 |
| POST | `/api/reset` | 恢复内置示例数据 |
| POST / PUT / DELETE | `/api/areas`、`/api/edges`、`/api/actors`、`/api/cues`（`/:id`） | 四类资源的增改删 |

其中 `edges` 资源字段：`{ a, b, seconds, closures }`，`closures` 为封闭时段数组 `[{ "start": 12, "end": 18 }]`（秒，左闭右开，可省略或为空数组）。

```
└── docker-compose.yml
```
